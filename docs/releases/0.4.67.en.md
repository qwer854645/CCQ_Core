# CCQ Core 0.4.67

Cumulative changes since **0.4.64**, including the fixes from 0.4.65, 0.4.66, and 0.4.67.

## Changes

- **Fixed Omni Speed Controller output differing from the configured RPM.** Ordinary shaft and gearbox receivers now receive the scrolled target RPM directly, without a nonzero theoretical input speed gate. Existing output feedback and recursion protection remain in place.
- **Fixed swapped Cooled / Frozen labels in JEI on multiplayer servers.** Heat requirements now sync by name, avoiding differences in enum ordering between the server and clients.
- **Fixed server exceptions during multiplayer ore vein scans.** Completing or cancelling scans and cleaning up disconnected players no longer invalidate session iteration.
- **Fixed block spout goggles tooltip exceptions.** Processing information can now be appended safely when the spout has an active process or recipe.
- **Fixed optional dependencies being treated as required.** Metadata now uses NeoForge's `required / optional` dependency types so compatibility features follow the installed mod set.
- **Fixed higher-tier coolant insertion into liquid snowman coolers containing lower-tier fluid.** Simulated and executed insertions now agree, allowing pipes to replace leftover water with higher-tier coolant as intended.
- **Fixed wasted lower-tier coolant while higher-tier cooling remains active.** Lower-tier fluid now waits until the current cooling expires before being consumed.

## Upgrading

Update both the server and clients to **0.4.67**. In particular, do not mix its heat requirement network format with 0.4.65. Existing worlds do not need to be reset.
